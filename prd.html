Pacific Aqua Sales System

Requirements locked from the client call: replace WhatsApp + Excel with a mobile field app and laptop admin on a local shop server. Phased v1 first; rolling/advanced routes later.

Mobile mockup Admin Control Raw markdown Call summary

1. Problem & goal

Field helpers log diya / mila / payment in WhatsApp; owner re-enters Excel (1–2 hrs/day). Pending dues and empty jars get missed. Ship two web apps on one ledger: mobile for helpers, backend on a shop PC for the owner. Excel becomes export-only.

4. Use cases (v1)

  1. UC-02 Field visit — customer → Check Balance → diya/mila + collection → save (offline OK).
  2. UC-03 Check Balance — money udhari + empty jars before delivery.
  3. UC-04 Route list — ~25 fixed stops by default; search for ad-hoc.
  4. UC-05 Offline sync — queue on phone → sync to shop server.
  5. UC-06 Admin order — pick customer + helper → mobile notification.
  6. UC-07 Monthly bill — customer lekhajokha → generate from seal template → print.
  7. UC-08 Ledger — month view + outstanding drill-down.
  8. UC-09 Inventory — plant lift, delivered, remaining stock.
  9. UC-10 Modules — Attendance, Expenses, Purchases as separate tabs.
  10. UC-11 Day trip — Load at plant → deliver → return unsold + empties (v1).

5. Functionalities

  • Visits / sales — WhatsApp replace: multi-product diya/mila, collection, remarks, PA-####
  • Check Balance — money dues + empty jars on one screen
  • Route customers — default list per helper; search for others
  • Offline sync — save on phone; sync to local shop PC
  • Orders — admin assigns helper; mobile notification inbox
  • Billing — customer-month jars given/taken, payments, pending → bill template
  • Ledger / dues — month register; outstanding; record payment
  • Inventory — plant lift, chittha, factory remaining
  • Attendance / Salary / Expenses / Purchases — Excel coverage, cleaner UX
  • Infra — local server + daily backup; HI/EN on mobile
  • Phase 2 — full Rolling start + advanced multi-vehicle isolation

8. Business rules

  • Visit numbers unique (PA-####); offline ids sync once (idempotent)
  • Status from amount paid vs total (Pending / Partial / Paid)
  • Empty-jar + money outstanding update after every visit
  • Voided visits kept for audit; excluded from revenue KPIs
  • Helpers see own visits + assigned orders; Admin sees all
  • Bill overlay uses client blank bill + seal image (no invented stamp)

9. v1 vs phase 2

v1: WhatsApp replace, Check Balance, route list, offline sync, order notify, ledger, bill generate, inventory lite, attendance/expenses/purchases, local server + backup.

Phase 2: Full Rolling start (mandatory godown lift), advanced multi-vehicle isolation, GST/e-invoice, native apps, accountant role build-out.
